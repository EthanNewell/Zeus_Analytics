# Проверка выпуска

Зафиксировать SHA образа, среду, время и проверяющего. Выполнять с подготовленными синтетическими данными.

1. `/health/live/` и `/health/ready/` отвечают 200. Неприменённые миграции дают ready=503.
2. Без входа реестр, карточка, CSV и документы перенаправляют на вход.
3. Неверный пароль не позволяет войти. Вход специалиста открывает реестр. `next` на внешний сайт не принимается.
4. Поиск, пагинация и переход в карточку работают. Происхождение и демонстрационная маркировка видны.
5. Результат проверки с обоснованием сохраняется от имени текущего пользователя. Вторая запись сохраняет первую.
6. CSV использует текущий фильтр, содержит маркировку и открывается с кириллицей. Значения, похожие на формулы, экранированы.
7. Документ доступен только с разрешениями; прямой URL хранилища не работает.
8. Пользователь без группы получает 403; специалист не управляет пользователями.
9. GET выхода не завершает сессию, POST завершает; запрос изменения без CSRF отклоняется.
10. Перезапуск web сохраняет БД и файлы. Повтор `seed_demo` не размножает записи и не перезаписывает правки.
11. На HTTPS-стенде cookie имеют Secure; HTTP перенаправляется на HTTPS; в ошибках нет отладочной страницы.
12. В журнале есть версия и request ID. После резервного копирования проверено восстановление в отдельной среде.

Пока адаптеры не подключены, POST импорта и анализа должен дать 501 без записи данных. Это ожидаемое поведение каркаса, но не готовность MVP. После подключения обязательна дополнительная проверка CSV → анализ → сохранённый результат и сверка с эталонными сценариями правил.
