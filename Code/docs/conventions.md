# Соглашения команды

Один проект Django, MySQL, шаблоны на сервере. Пользовательские подписи — на русском; код, URL names и идентификаторы — на английском. Стиль задаёт Ruff.

## Изменения кода

Короткие ветки, один понятный результат на PR. Описание PR содержит поведение, способ проверки и сведения о миграциях. Слияние после проверки напарником и успешного CI. Предметные миграции координирует №2, пользовательскую модель и окружение — №1. В ветках, созданных агентом, используем префикс `codex/`.

Изменения общей модели и контрактов сопровождаются обновлением примера и тестов потребителей. Общие миграции проверяются на чистой БД и при обновлении предыдущей версии. Выпущенные миграции не редактируются.

## Границы логики

- `views.py`: HTTP, разрешения, форма и ответ.
- `forms.py`: проверка пользовательского ввода.
- `services.py`: операции записи и транзакционные границы; права также проверяются в публичных сервисах записи.
- `selectors.py`: повторно используемые запросы чтения.
- `analysis/rules/`: правила; модель и HTTP-слой не содержат формул индикаторов.

`cases` не импортирует интерфейс. `analysis` читает подготовленные факты; `dashboard` собирает результаты. Новые страницы закрыты `LoginRequiredMiddleware`. Публичный маршрут требует явного `login_not_required` и проверки отсутствия данных в ответе.

## Данные

UUID — для предметных сущностей; кадастровые номера и ИНН — строки. Даты без времени — `DateField`; моменты времени — UTC с timezone, интерфейс — МСК. Деньги и площади — `Decimal`, единицы указываются в контракте.

Неизвестное значение отличается от `False`, нуля и «не применимо». У правила четыре статуса из `analysis.contracts.RuleStatus`. Приоритет и полнота — отдельные характеристики. Никакого «процента коррупции».

До рабочего импорта №2 расширяет модель: происхождение каждого значимого поля, координаты в исходном файле, первоисточник и статус сверки. Значение `author_marked_real` означает маркировку автора, не независимую проверку. Цвет Excel преобразуется в явные признаки. Вывод, использующий синтетический вход, демонстрационный, включая расчётные зависимости.

Изменения состояния выполняются POST с CSRF. Форма не принимает автора/время проверки: их назначает сервер. История добавляется отдельными записями; операции изменения/удаления истории через интерфейс и Django Admin не предоставлены. Для строгой неизменяемости также на уровне ORM/SQL необходима отдельная политика БД.

## Секреты и файлы

`.env`, БД, пользовательские файлы, резервные копии и локальные окружения исключены из Git. Веб-процесс не получает root-пароль БД на стенде. В журнал запросов попадают route name, request ID, статус, время и версия; содержимое форм и query string не пишется.

Новые загрузки должны проверять размер, допустимый тип и принадлежность файла случаю. Внутреннее имя формирует сервер. Прямые URL `MEDIA_URL` не публикуются; скачивание требует разрешений. Пользовательский текст экранируется шаблонами, CSV защищается от интерпретации строк как формул.

## Готовность задачи

Автор проверил свой участок, CI прошёл, миграции воспроизводимы, изменение проверено на стенде. Заглушка 501 не считается реализованным импортом или правилом. Документирование ограничений не заменяет проверку фактического сценария.
