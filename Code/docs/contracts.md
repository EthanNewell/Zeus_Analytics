# Контракты интеграции

## Доступ

`AUTH_USER_MODEL=accounts.User`, вход по username, сессии в БД. Учётные записи создаёт администратор. `bootstrap_roles` после миграций идемпотентно синхронизирует группу `Specialist`; группа не получает управление пользователями и Django Admin.

| Операция | Требуемые разрешения |
|---|---|
| Реестр и карточка | `cases.view_case` |
| Выгрузка | `cases.view_case`, `cases.export_cases` |
| Документ | `cases.view_case`, `cases.view_evidence` |
| История на карточке | `cases.view_review` дополнительно к карточке |
| Добавление проверки | `cases.view_case`, `cases.add_review` |
| Импорт | `cases.view_case`, `cases.import_cases` |
| Анализ | `cases.view_case`, `cases.run_analysis` |

Гость перенаправляется на вход; вошедший без разрешения получает 403. Разрешения действуют на общий набор случаев одного подразделения.

## Импорт — №2

`imports.services.import_table(actor=..., uploaded_file=...)` → `imports.contracts.ImportResult`: UUID загрузки и UUID затронутых объектов при успехе либо ошибки (строка, поле, код, пояснение). Коды: `no_file`, `too_large`, `format`, `unreadable`, `unknown_table`, `missing_column`, `required`, `invalid_value`, `duplicate`, `no_object`, `too_many_rows`, `empty`. При любой ошибке ничего не записывается (вся запись — одна транзакция после полной проверки).

Формат — таблица исследования как есть: `.xlsx` или `.csv` (UTF-8 или cp1251, `;` или `,`). Строка заголовков ищется в первых пяти строках и сопоставляется с `cases.indicators.INDICATORS` (не меньше 80 % колонок). Однострочные записи под таблицей — примечания набора; строка, начинающаяся с «Источники», — источники.

Ячейка → факт `{"value", "state", "origin", "cell", "label"}`. `state`: `present`, `missing` (пусто, «нет данных», «нет даты»), `absent` («—»: события не было / не применимо). `origin`: жёлтая заливка → `author_marked_real`, формула → `calculated`, остальное в Excel → `synthetic`, CSV → `unknown`. Даты — ISO, числа — JSON-числа, координаты (`широта долгота; …`) и WKT POLYGON проверяются при импорте.

Ключ записи — колонка `key_column` индикатора; повторная загрузка обновляет `Record` с тем же `(indicator, source_key)`. Объекты (`Case`) находятся по кадастровому номеру (полные номера, сокращения «:1544», диапазоны «:3352 – :3356»); у объекта без номера ключ — хэш описания. Колонка «Соответствие индикатору» сохраняется в `Record.author_mark` как эталон.

Лимиты `MAX_IMPORT_BYTES` (2 МиБ) и `MAX_IMPORT_ROWS` (500) проверяются сервисом.

## Анализ — №3

`analysis.services.run_analysis(actor=..., case_ids=None)` проверяет права, считает каждое правило по каждой записи (или по записям указанных объектов) и сохраняет `AnalysisRun` и неизменяемые `RuleOutcome`. Повторный запуск создаёт новые результаты, старые остаются.

`RuleOutcome`: `run`, `record`, `rule_code`, `rule_version`, `status` (`triggered`, `not_triggered`, `insufficient_data`), `priority` (`low`, `normal`, `high`), `explanation`, `metrics` (подпись, значение), `used_fields`, `missing_fields` (обязательны для `insufficient_data`), `expected_status` (из разметки автора), `is_demonstration`.

Правило — функция в `analysis/rules`, зарегистрированная в `RULES` с версией; читает только исходные факты, расчётные колонки таблицы не использует. Риск объекта (`Case.attention`) считает `analysis.services.summarize`: наибольший вес (`Indicator.risk`) среди сработавших индикаторов — высокий, средний или низкий; если ничего не сработало, но данных не хватило, — «нет данных»; иначе «сигналов нет». Веса взяты из таблицы исследования «Индикаторы и источники данных Р1 и Р2».

## Карточка и история — №5

`cases.services.add_review(actor, case, outcome, comment)` проверяет разрешение и создаёт новую запись с серверным автором и временем. Допустимые исходы — `confirmed`, `not_confirmed`, `needs_information`; их подписи описывают результат проверки сотрудника. Исходные факты не изменяются.

Вложения выдаются GET `/evidence/<uuid>/download/` с `Content-Disposition: attachment`. Физический URL хранилища не открывается. Перед добавлением загрузки нужно согласовать допустимые типы, размер и связь с фактом. URL документа и реквизит источника — разные данные.

## Контроль первого подключения

CSV → запись с происхождением → реальный запуск → сохранённый результат → карточка → запись специалиста → выгрузка. Проверить положительный, отрицательный, неполный и неприменимый случаи; сейчас каркас покрывает вход, карточку, историю и выгрузку, а не этот полный цикл.
