# Контракты интеграции

## Доступ

`AUTH_USER_MODEL=accounts.User`, вход по username, сессии в БД. Учётные записи создаёт администратор. `bootstrap_roles` после миграций идемпотентно синхронизирует группу `Specialist`; группа не получает управление пользователями и Django Admin.

| Операция | Требуемые разрешения |
|---|---|
| Реестр и карточка | `cases.view_case` |
| Выгрузка | `cases.view_case`, `cases.export_cases` |
| Документ | `cases.view_case`, `cases.view_evidence` |
| История на карточке | `cases.view_review` дополнительно к карточке |
| Добавление проверки | `cases.view_case`, `cases.add_review` |
| Импорт | `cases.view_case`, `cases.import_cases` |
| Анализ | `cases.view_case`, `cases.run_analysis` |

Гость перенаправляется на вход; вошедший без разрешения получает 403. Разрешения действуют на общий набор случаев одного подразделения.

## Импорт — №2

Точка подключения: `imports.services.import_csv(actor=..., uploaded_file=...)`. Контракт ответа — `imports.contracts.ImportResult`: UUID загрузки и UUID случаев при успехе либо ошибки с номером строки, полем, кодом и пояснением. При ошибках предметные данные не сохраняются. Сейчас адаптер всегда выбрасывает `ImportNotConfigured`; view отвечает 501.

До замены адаптера согласовать обязательные колонки, кодировку, разделитель, формат дат/чисел, неизвестные значения, происхождение полей и ключи дублей. Лимиты `MAX_IMPORT_BYTES` (по умолчанию 2 МиБ), `MAX_IMPORT_ROWS` (500) — предварительные, должны применяться обработчиком и уточняются измерением. Настройки Django ограничивают тело запроса, но сами по себе не проверяют число строк и все способы загрузки.

После реализации: отдельная проверка прав в сервисе, полная валидация до записи, транзакция, устойчивость к повторному запросу и ограничение памяти/времени. Добавить `ImportBatch`, страницу результатов и перенаправление успешного POST в `imports.views.upload`. Не оставлять интерфейс «модуль не подключён» после подключения сервиса.

## Анализ — №3

Точка подключения: `analysis.services.run_analysis(actor=..., case_ids=...)`. Сейчас она выбрасывает `AnalysisNotConfigured` до любых вычислений; POST `/analysis/run/` возвращает 501.

`RuleResult` — неизменяемый объект обмена, ещё не модель БД:

| Поле | Значение |
|---|---|
| `case_id`, `analysis_run_id` | UUID случая и запуска |
| `rule_code`, `rule_version` | Стабильный код и версия |
| `status` | `triggered`, `not_triggered`, `insufficient_data`, `not_applicable` |
| `priority` | `low`, `normal`, `high` |
| `explanation` | Непустое объяснение |
| `used_fact_ids`, `evidence_ids` | Идентификаторы фактов и источников |
| `missing_fields` | Недостающие данные; обязательно для `insufficient_data` |
| `is_demonstration` | Использован синтетический вход или производный от него факт |

№3 добавляет `AnalysisRun` и хранимый результат, снимок/неизменяемую версию фактов, параметры территории/периода/отбора. Сервис проверяет права, UUID, доступ к каждому случаю и непустую область запуска. View успешного POST перенаправляется к реальному запуску. Затем №4/№5 заменяют надпись «Не запускался» и `analysis_status=not_run` в карточке, реестре и CSV на реальные результаты.

Коды И из файлов не отождествляются с Р1 без отдельной таблицы соответствия. Р1.8 — контекст; самостоятельно не задаёт высокий приоритет. Отрицательный результат не означает отсутствия риска за пределами обработанной выборки.

## Карточка и история — №5

`cases.services.add_review(actor, case, outcome, comment)` проверяет разрешение и создаёт новую запись с серверным автором и временем. Допустимые исходы — `confirmed`, `not_confirmed`, `needs_information`; их подписи описывают результат проверки сотрудника. Исходные факты не изменяются.

Вложения выдаются GET `/evidence/<uuid>/download/` с `Content-Disposition: attachment`. Физический URL хранилища не открывается. Перед добавлением загрузки нужно согласовать допустимые типы, размер и связь с фактом. URL документа и реквизит источника — разные данные.

## Контроль первого подключения

CSV → запись с происхождением → реальный запуск → сохранённый результат → карточка → запись специалиста → выгрузка. Проверить положительный, отрицательный, неполный и неприменимый случаи; сейчас каркас покрывает вход, карточку, историю и выгрузку, а не этот полный цикл.
