# ТЗ №4. Общий интерфейс, загрузка и реестр

**Исполнитель:** разработчик №4. **Принимает:** №5; сервис импорта проверяет №2, семантику отбора и сводки — №3. Прочитать [общие контракты](00-shared-contracts.md). Результат: специалист загружает данные, понимает итог и находит нужный случай без ручного обращения к БД.

## 1. Область ответственности и файлы

Реализовать `Code/templates/base.html`, общую навигацию/стили в `Code/static/`, шаблоны и views реестра, формы/views/шаблоны импорта. Предметный парсер и запись импорта — №2. Запуск анализа и его POST — №3. Карточка, форма проверки, экспорт и выдача документов — №5. Вход и роли — №1; использовать его маршруты и разрешения.

Координировать общие `dashboard/urls.py`, `dashboard/selectors.py` и договорённости о контексте шаблонов с №5. Расчёты правил, приоритетов и демонстрационности не дублировать в JavaScript или шаблонах.

## 2. Общий макет

Сделать единый русский интерфейс: название сервиса, ссылки «Реестр»/«Загрузка», имя пользователя, POST-выход с CSRF, сообщения об успехе/ошибке и место для request ID. Страницы наследуют `base.html`; общие компоненты статусов, происхождения, источников и полей формы доступны №5.

Статусы и приоритеты сопровождаются текстом, а не только цветом. Нужны подписи полей, клавиатурный доступ, видимый фокус, читаемые таблицы и сообщения. Проверить как минимум обычный ноутбук и узкое окно: таблица может иметь горизонтальный скролл, элементы формы не перекрываются. Отдельная мобильная версия не требуется.

Пустой реестр, отсутствие результатов фильтра, отсутствие анализа, серверная ошибка и запрет доступа имеют разные понятные состояния. Скрытая кнопка не заменяет серверную проверку разрешения. Заглушки 14 ноября видимо обозначаются; с 15 ноября основной путь читает реальные модели.

## 3. Загрузка CSV

GET/POST `/imports/` (`imports:upload`): поле файла, краткая инструкция, ссылка на текущий синтетический пример, версия формата, размер/количество строк и предупреждение о смешанных данных. Формат и лимиты берутся из согласованной конфигурации, не расходятся с парсером №2. Форма — multipart, CSRF; право импорта проверяется на сервере.

POST вызывает один сервис `import_csv`, без второй реализации парсинга в view. Повтор ключа формы не создаёт дубли. В процессе отправки можно заблокировать кнопку для удобства, но защита от повторов остаётся серверной. Ошибки валидации файла/формы показываются у соответствующего поля.

После обработки перейти на `/imports/<batch_id>/` (`imports:detail`):

- Статус `completed`, `rejected` или `duplicate` с русской подписью, автор и время, версия формата.
- Созданные/пропущенные записи, предупреждения о происхождении и полноте; список/ссылка на загруженные случаи.
- При повторе — ссылка на исходную загрузку; при отклонении — явное сообщение, что предметные данные пакета не сохранены.
- Ошибки таблицей: номер строки, поле, код, понятное описание. Большой список пагинировать/ограничивать отображение с явным общим числом, не теряя сам журнал.
- Действие «Открыть случаи этой загрузки» и возможность запуска анализа на явно указанной области; не запускать анализ автоматически при GET.

Не показывать полные персональные строки или traceback. Повторное открытие итога через URL должно работать после перезапуска приложения. Авторизованный пользователь без права просмотра загрузки получает 403.

## 4. Реестр и фильтры

GET `/cases/` (`dashboard:case_list`) использует единый `select_cases` из общих контрактов. Минимальные колонки: ID случая/кадастровый номер, территория, дата/тип исходного события, сработавшие правила и их статусы, приоритет, полнота, демонстрационность/неуточнённое происхождение, последний исход проверки, ссылка в карточку.

Показывать, какой запуск выбран, его время и устаревание при обновлённых входах. Случай без анализа имеет состояние «не анализировался», а не «не сработал». Несколько RuleResult не создают несколько одинаковых строк случая. ВРИ и категория не объединяются в одно поле «тип земли».

Минимальный набор фильтров: кадастровый номер/ID, территория, период исходных событий, код/статус правила, приоритет, последний исход проверки (включая «не проверен»), демонстрационные результаты. Даты проверяются сервером: неверный формат и начало после конца возвращают ошибку формы без 500. Период фильтрует согласованный вид события, не дату импорта.

Фильтры передаются GET-параметрами, сохраняются в пагинации, ссылке экспорта и возврате из карточки; есть «Сбросить». Порядок строк стабилен с дополнительным ключом UUID; сортировка по приоритету использует установленный порядок, не алфавит. Размер страницы зафиксировать в конфигурации. Произвольные имена полей сортировки не передавать в ORM.

## 5. Сводка и запуск анализа

Сводка относится к текущим фильтрам: число уникальных случаев, случаи с основным сигналом, с недостаточными данными, не проверенные сотрудником и демонстрационные. №3 фиксирует критерии. Один случай может входить в несколько групп — рядом пояснить, что суммы могут не совпадать. Контекст Р1.8 отдельно от основных сигналов, без подписи «выявлена коррупция». Не показывать нули как результат анализа до первого запуска.

Кнопка «Запустить анализ» отправляет POST в `analysis:run`, с CSRF, ключом повтора и валидируемыми параметрами области. Перед отправкой видно число случаев, территорию, период и критерий отбора; применяется вся выборка, не только текущая страница. При изменении выборки после открытия страницы сервер фиксирует реально обработанные case ID и показывает итог. При пустой выборке — понятное сообщение, без фиктивного успешного анализа. Ошибка анализа не скрывает предыдущие успешные результаты.

Ссылка выгрузки ведёт на `dashboard:case_export` с теми же фильтрами, без `page`; обработку делает №5. Возвратный адрес из карточки должен быть локальным и проверенным, без открытого редиректа.

## 7. Приёмка

- [ ] Без входа данные закрыты; без права импорт/анализ/экспорт недоступны и на сервере.
- [ ] Корректный, ошибочный, повторный и неполный CSV дают разные понятные результаты; после ошибки предметных записей нет.
- [ ] Кириллица и текст с HTML отображаются корректно и экранируются.
- [ ] Все четыре статуса, отсутствие анализа, устаревшие результаты, полнота и происхождение различимы.
- [ ] Фильтры, границы периода, пагинация, сброс и возврат из карточки работают предсказуемо.
- [ ] При сочетании кода и статуса правила фильтр относится к одному RuleResult; счётчики не умножаются из-за JOIN.
- [ ] Запуск включает всю заявленную выборку, сохраняет область; повтор POST не дублируется.
- [ ] Реестр, сводка и CSV используют один отбор; пустая выборка не приводит к ошибке.
- [ ] Основной путь проходит на стенде без заглушек, интерфейс читаем в обычном и узком окне.

Автоматически проверить HTTP-права, формы и семантику фильтров на согласованных фикстурах с MySQL; визуальную пригодность и путь пользователя проверить вручную с №5. Тесты, повторяющие только HTML-разметку, не требуются.
