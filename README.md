# Риски в кадастре

Рабочее место специалиста по профилактике коррупции в земельных отношениях: сопоставляет сделки с землёй, смену категории, правки ПЗЗ и связи с должностными лицами, показывает основания для проверки по каждому объекту.

Демо для просмотра: <https://oskarasadullin.github.io/kod-prozrachnosti/> · код: <https://github.com/EthanNewell/Zeus_Analytics>. Команда Zeus Analytics, хакатон «Код прозрачности». Django 5.2 LTS, Python 3.12, MySQL 8.4.

Реализовано: вход по ролям → загрузка таблиц исследования (xlsx/csv) с происхождением каждой ячейки → семь правил с версиями (И1, И2, И3, И4, И6, И8, И10) → реестр с приоритетом → карточка с объяснением, хронологией и исходными фактами → запись проверки сотрудника → CSV. Сверка с разметкой автора исследования на наборе исследования — 69 из 70: сработало 31, не сработало 35, недостаточно данных 4. В правиле И6 сервис сам ищет ИНН участника решения среди ИНН покупателя, его учредителей и руководителя (текущих и прежних) и сверяет результат с отметкой исследователя; связь через промежуточное юрлицо, которого нет в данных, берётся из отметки. В правиле И10 сервис считает эпизоды из перечня исследователя, объекты которых есть в таблицах других индикаторов; участие лица в эпизоде — по записи исследователя. Автоматическая загрузка выгрузок ЕГРЮЛ — задача пилота. На 13 реальных земельных торгах из открытых данных ГИС «Торги» (torgi.gov.ru, Ростовская область, выгрузка 19.11.2026, набор `Code/real_data`) правило И4 сработало на 9 лотах — единственный участник, цена договора равна начальной — и не сработало на 4, где цена выросла. 66 тестов проходят локально на SQLite; GitHub Actions на каждое изменение запроса на слияние запускает их на MySQL 8.4, [последний запуск](https://github.com/EthanNewell/Zeus_Analytics/actions/runs/44457017699) успешен. Запуск и состав описаны в [Code/README.md](Code/README.md), результаты проверки — в [журнале](Code/docs/verification.md).
